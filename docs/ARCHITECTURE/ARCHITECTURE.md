### Where the verifiers stop (the border)

**A verifier cannot cover every violation of a stated invariant, and this one does not claim to.** The rules are human-authored intent; a static checker reaches only the part of that intent expressible as a property of source. The border is stated here so a `PASS` is read as "this check held", never as "this rule is safe":

- **Reachability is name-merged, not type-inferred.** The graph keys on bare function/class names, so a name collision across modules could invent an edge or mask one. It resolves aliases and argument-passed callables; it does not resolve `getattr`, dynamic import, or dispatch through a variable.
- **"Dead code" means statically unreachable.** A site reached only at runtime — a plugin hook, a string-named import — would be reported dead while being live.
- **Source is not behaviour.** These verifiers read code, never a running system. They cannot observe what an operator or a subagent actually did.
- **Intent is out of reach entirely.** R6 asks whether a human authored a body; code can show that no server path *synthesised* one, and nothing more. That gap is why R6 reports PARTIAL rather than PASS, and why the SOT's CONVENTION tier stays accurate.

Everything past that line is the Architect's judgment, not the map's. Reporting the limit IS the deliverable: a checker that overstated its reach would be the advisory theater these rules exist to prevent.
